# tidelock — lessons & gotchas (one line each; read before build work)

- **IDE = VS Code + CMake Tools (presets) + clangd + CodeLLDB**; no Visual Studio solutions. `.vscode/` is committed; put machine-local tweaks in `.vscode/*.local.json` (ignored). Toolchain on this PC: LLVM 22.1.7 (`C:\Program Files\LLVM\bin`), CMake 4.3, Ninja 1.13, Python 3.13.
- clangd reads `.cache/compile_commands.json`, which CMake Tools copies from the active preset — configure once before expecting diagnostics.
- Binaries land in `out/<preset>/bin/`; `out/` and `.cache/` are ignored.
- **clang-cl is a `cl` driver, not a `clang` driver**: `-Wall` there means MSVC's `/Wall`, which clang maps to `-Weverything` (`-Wc++98-compat` on every C++20 line). Use `/W4 /WX`, `/EHs-c-`, `/GR-`, `/Zc:threadSafeInit-`, `/clang:-nostdinc++`; the other `-W`/`-f` flags are the same in both modes (`docs/BUILD.md` §9 R-6).
- `CMAKE_BUILD_TYPE` is forced empty — tiers own the flags. Leave it and CMake silently appends its own `/Ob0 /Od /RTC1 -MDd` set, which is a `build_id` input nobody chose (`docs/BUILD.md` §9 R-5).
- CMake presets are only read from `CMakePresets.json` at the repo root; ours is two lines that `include` `cmake/presets.json`.
- In CMake regexes write parentheses as `[(]` / `[)]`: quoted-argument escaping and the regex engine disagree about backslashes, and a mis-escaped pattern silently matches nothing (it cost a build cycle in the test-list generator).
- A static lib needs at least one TU: every empty module folder carries one placeholder `.cpp` until its lane lands. Module sources are globbed with `CONFIGURE_DEPENDS`, so a lane adds files without editing another lane's CMake.
- `tl_foundation_det` vs `tl_foundation` is split by an explicit NON-det stem list — anything new defaults to the audited half, so a mistake fails the symbol audit loudly instead of escaping it.
- An audit is worth what its **negative test** is worth. The W0 gates passed every obvious plant and let five adversarial ones through (`f32` instead of `float`, a basename collision across exempt lists, an anonymous-namespace global, an upward `#include`, an upward symbol reference). Plant the clever violation, not the obvious one.
- Regexes cannot see mutable globals — anonymous namespaces, `inline static`, dynamic initialisers all evade them. `llvm-objdump -h` and a zero-`.data`/`.bss` rule can, and cost nothing.
- `build_id` over a *flag string* is a lie: compile definitions, `-std`, `CXXFLAGS` from the environment, `cmake/` edits and git-ignored sources all bypass it. Hash the resolved compile commands (`compile_commands.json`) plus the content of the files they name.
- `[[nodiscard]]` cannot attach to a typedef. An error code that must not be discarded has to be an `enum`, not `using ErrCode = u16`.
- A doc sentence that names no tool ("the fingerprint tool asserts it") is a phantom gate; grep for the tool before believing it.
- `build_id` had to answer one question, and it was answering two: "are we the same program?" (must be target-independent, or PC + Deck + Pi peers can never hand-shake) and "what exactly built this binary?" (compiler, triple, flags). Two questions, two values: `build_id` is compared, `build_env` is reported (`docs/BUILD.md` §9 R-8).
- clang spells it `-std=c++20`, clang-cl `-std:c++20`. Normalise driver spellings before they reach a hash, or two targets disagree on a value that is supposed to be identical.
- The audit selftest found four bugs in its first run - two in the fixtures, one in the new `build_id`, one real gate hole (a header's contract block was counting as the first function's contract comment). Write the negative test the same day as the gate.
- Fixed point is not enough on its own: `char` is signed on x86-64 and **unsigned on aarch64**, and `long` is 32-bit on Windows and 64-bit on Linux. A PC peer and a Pi peer diverge on either with no UB anywhere. The determinism moat needs the fixed-width vocabulary *enforced*, not just intended (`tools/audit/includes.py` bans them in sim TUs).
- A `static` function is internal linkage, not state. The `^static [^c]` grep in `CPP-SUBSET.md` §1 rejected every one of them — the gate would have blocked the first real `.cpp` written. Mutable-global detection belongs at the link stage (`.data`/`.bss`/TLS), not in a regex.
- `.data.rel.ro` is const data holding relocations, and PIE (the Linux/Pi default) is where const function-pointer tables land. A `.data` prefix match rejects it — passing on Windows and failing every lane in CI.
- `'` in C++ is a digit separator as often as a character literal (`1'000u`). A naive literal-stripper treats the rest of the file as a string and every token ban downstream goes silent.
- A gate that is only exercised by fixtures its own author wrote proves nothing. R-8 ("one `build_id` for every target") is now checked by building netcode-win and netcode-linux from one checkout in CI and diffing `build_id.txt`.
- Removing an input from a hash invalidates every argument that leaned on it. Taking the compiler out of `build_id` silently voided R-7's "an off-pin peer cannot join" — in the same document, in the same commit.
- Fixed-width types are not enough either: **bit-field layout** differs between windows-msvc and linux/aarch64 (measured: `{u8 a:4; u16 c:8;}` is 4 B vs 2 B), and `usize` as `size_t` is a different *type* per target even at the same width, so a `usize`-keyed template selects different code. Both are banned in sim TUs; `usize` is now `u64`.
- `const char*` is legal in sim code for message literals — which re-opens the `char` hole one level down: `(u64)s[i]` over a byte ≥ 0x80 sign-extends where `char` is signed. Sim **string literals** must be ASCII; comments are free (they never become char data).
- Backslashes do not survive this shell's heredocs: `` in a regex arrived as a literal backspace byte (``), so four new bans compiled fine and matched nothing. Print `pattern` after generating a regex programmatically.
- A patch script that asserts before writing loses every earlier edit in the same run. Three bans "landed" and vanished; only the selftest noticed.
- **Check CI before writing "verified" in a commit message.** Three pushes went out claiming verification while four jobs were red on main - including the job built to prove R-8. A green local run is evidence about the local machine, nothing more.
- A compile line is not whitespace-separated. CMake >= 4.4 quotes `"C:/Program Files/LLVM/bin/clang-cl.exe"`; `cmd.split()` made `build_id` depend on whether the compiler's install path contained a space. Use `shlex`.
- Dropping a flag but keeping its separate argument is worse than keeping both: `-isystem <dir>` and `-imsvc<dir>` became different token sets for the same directory.
- An exemption carved for one rule silently applies to every rule sharing the flag. `tl_types.h` was exempt from the float ban - and therefore from the bit-field, platform-macro and section bans too, in the one header every sim TU includes.
- A gate that compares two empty lists passes everything. `clang -E` line markers escape backslashes (`# 1 "C:\dir\f.cpp"`), so normalising `\` to `/` produced `c://dir//f.cpp`, matched nothing, and the cross-target gate reported 0 divergences on planted violations. It now fails loudly if no line of our own source reached the comparison.
- `-nostdinc` drops clang's resource dir as well as the platform's headers; `-nostdlibinc` keeps the freestanding `<stdint.h>`/`<stddef.h>`/`<limits.h>` and drops only the system ones. That difference is what lets the cross-target gate run with no sysroot.
- Two of four "the gate missed it" findings were wrong fixtures, not wrong gates: `#pragma pack(1)` alone packs identically everywhere, and `__GNUC__` is already undefined for the windows-msvc triple under the clang driver. Verify the fixture before believing the failure.
- **A filter must never decide what gets compared.** Twice now the same bug: a path filter that matched nothing compared two empty lists, then a record comparison keyed by a name parsed out of a dump dropped anonymous-namespace, unnamed-typedef, same-named-local and `__`-prefixed records. Both were silent passes. Compare positionally with a count check; use names only in messages.
- Filter sets must be **measured, not guessed**. The system records to skip now come from dumping a TU that includes only the sanctioned headers - a prefix match on `__`/`max_align_t` was user-controllable, so a struct named `__Cell` vanished.
- Normalising a difference away is as dangerous as failing to see it: stripping integer suffixes made `1LL` identical to `1` and hid a 64-bit-vs-32-bit shift. **Map** spellings to a canonical form that preserves width; never delete.
- `int64_t` is `long long` on windows-msvc and `long` on linux/aarch64 - the same type, two spellings. Every `fx<i64,FRAC>` in a layout dump reads as divergent until they are canonicalised.
- "0 false positives on this tree" is worth nothing when the tree is 13 placeholder files. Test a gate against the code that is about to be written, not the code that exists.
- A `static_assert` message is a string literal to the non-ASCII gate: `"docs/X.md §3.1"` fails a sim TU. Spell `section 3.1` in messages; comments are free.
- `using pos_t = fx<i32,18>` and `using invmass_t = fx<i32,18>` are ONE type: every "per row" trait, overload or op-table line collides with its format twin (the first fx_palette.h had six redefinitions). Key tables by format, or tag the rows (RR-5).
- Let the compiler check every documented constant: `static_assert(G_SUBSTEP.v == 21432)` failed - the doc's arithmetic was wrong, not the code. A raw value in a doc is a claim until a `static_assert` has seen it.
- A 2^30-entry reference table cannot be committed; an exhaustive sweep lives in `tools/` (doubles allowed), its worst cases are re-verified at 60 digits, and the MEASURED bound is a constant the unit tests assert against. "<= 2 ulp" in a spec written before the kernel existed was a guess (it measured 9.06).
- The trap stub of `tl_fatal` gives no message: a `TL_ASSERT` in a test shows as exit `0xC000001D` with nothing printed. Find it with `tl_tests --filter <name>` per test, or a scratch `main` that includes the `.test.cpp` and defines a printing `tl_assert_failed`.
- A seeded property test over full-range inputs will leave the helper's contract (`mul<angle_t>(omega_t, H)` at 2048 turn/s is 4 turns) and trap in dev. Generate inside the contract and COUNT what was tested, or the test is vacuous where it passes and a trap where it does not.
- The `(s + 1.5*2^23) - 1.5*2^23` rounding identity is exact only for `|s| <= 2^22`: above that the sum crosses 2^24, where a float's spacing is 2, and every odd integer comes back even. Use `2^23` per sign (`2^52` for doubles). The round-trip test tolerated 1 ulp - the exact size of the bug - so it passed; a tolerance must be derived from the claim, not from what makes the test green.
- **UBSan recovers by default.** It prints the report and the process exits 0, so a sanitizer CI lane without `-fno-sanitize-recover=all` is a log, not a gate: a signed overflow was reported in a green run of the W1 fx lane. Read the lane's log once, not just its badge.
- A float needs no `float` token: `decltype(1.0) x`, `auto y = 0x1p3`, `k * 1e3`, `_Float16`; a `long` needs no `long` token: `decltype(1L) x`. Token bans need literal bans beside them, and a local never reaches the layout gate.
- A pinned trace hash proves exactly the helpers the trace calls on the inputs it draws, nothing more. List what it skips in the test, or add a second pin; "1M values" is a size, not a coverage.
- A seeded property test's in-range count must be asserted PER generator, never as a sum: sixteen rows summed to "> 8N" lets one vacuous row hide behind fifteen full ones.
- The generated test list registers every `TL_TEST(` in the tree, `#if` or not: a tier-conditional test puts the `#if` INSIDE the body (with a trivial check on the other branch), or the link fails with an undefined `test_*`.
- A `TL_ASSERT` that fires inside a test is a silent `0xC000001D` under the trap stub; the fastest way to find it is a scratch `main` that `#include`s the test body with a printing `tl_assert_failed` (it found `fx.h:272` and a bad divisor in trace B in under a minute each).
- Patching a source file through a Python non-raw triple-quoted string eats `\` + newline: a multi-line macro's continuations vanish and the macro becomes one 400-column line that still compiles. Use raw strings or the editor for anything with line continuations.
- A zero-on-push that starts at the aligned block start misses the **alignment gap** [old used, start): the gap enters [base, used), which is exactly what the state hash covers, so a reused-then-realigned registered arena hashes stale bytes with no UB anywhere. Zero from old `used`, and test the gap, not just the block.
- A vendored header can fail the cross-target layout gate for a branch that never executes: rapidhash.h's `#ifdef _MSC_VER` pulls in `<intrin.h>` on the win triple regardless of `__SIZEOF_INT128__` (clang predefines `_MSC_VER` for MSVC-triple compat, and its own resource-dir `intrin.h` then declares ~90 SIMD-intrinsic records linux/pi never see) even though the `_MSC_VER` multiply path is dead code on every target we build for. Stub the header (`intrin.h`, next to the existing `string.h` stub), never `-U` the macro: the first fix passed `-U_MSC_VER` in `BASE_FLAGS` and the gate then reported "0 divergences" for a sim TU that was literally two programs (`#ifdef _MSC_VER` around two different structs), because `_MSC_VER` is the ONE platform macro clang predefines for a triple we actually ship.
- **Undefining a macro to silence a gate deletes the gate, not the noise** - and the negative fixture that would have caught it did not exist because `__GNUC__`'s fixture "already covered macro branches": `__GNUC__` is undefined for the win triple, so that case never exercised the win-vs-linux leg at all. One fixture per macro that is predefined for a shipped triple.
- Vendoring a library that lives outside `src/` still needs two separate gate entries, not one: `tools/audit/includes.py`'s `SYS_ALLOW_DIRS` (which directory may spell the system include at all) and its `BACKEND_HEADERS` (which directory is its wrap module) check independently, and `tools/audit/targets.py` needs the vendor dir on its own `-I` list since it preprocesses standalone with no CMake target to inherit include dirs from.
- A golden computed by running the code it guards is a screenshot, not a known answer. Both hash families' vectors were "computed from the pinned implementation"; they turned out correct, but nothing in the test could have said so. `tools/rapidhash_ref.py` re-derives them from the algorithm in another language - the cheap independence that catches a wrong config branch, seed, secret or unroll boundary.
- A `[0, 1)` fraction does not make a `[lo, hi)` range: `lo + mul<R>(q, hi - lo)` rounds RNE, so every span under 2^29 raw units rounds its top draw up to exactly `hi`. And `hi - lo` is the row's *wrapping* subtract - `rng_range<pos_t>(r, -WORLD_HALF, WORLD_HALF)` wrapped the span to `INT32_MIN` and returned positions kilometres outside the world with no assert, while the test asserted `<= hi` and passed.
- A gate exemption keyed on a bare filename stem is not scoped at all: `log`, `prof`, `probe` and `crash` are ordinary words, and `symbols.py` matching the archive member's stem alone exempted a `log.o` in ANY `--data-only` lib - every non-audited lib in `src/`. The twin rule in `includes.py` was scoped to `src/foundation/` and looked identical in the diff. An exemption is a stem INSIDE a named scope; write the scope down or the gate has a hole the size of the vocabulary.
- The one header that crosses a firewall is the one an exemption must never touch: `tl_assert.h` is on the tooling stem list AND is the single tooling header a sim TU may include, so a stem-keyed io/state grant handed both to every det TU in the tree. `#include <stdio.h>` + a mutable global appended to it produced 0 violations.
- `#if UNDEFINED_MACRO <= 0` is true, silently: `TL_LOG_MIN` was specified per tier in `TOOLING.md` and defined in no build file, so every tier compiled in `TL_LOG_TRACE` and the compile-out test's `#else` arms were dead code in every tier it was ever built for. A tier-conditional constant that a header reads must be `#ifndef`-guarded with a derivation, not assumed present.
- A test whose `#if` mirrors the header's `#if` cannot fail on the branch the current tier does not take. To test a compiled-out call site, pin the gating macro in the test TU itself (before the include) so the barred branch is exercised in every tier.
- A `slow` tag does not keep a destructive test out of a run: the runner selects every test when no `--tag` is given, so a `TL_FATAL` trigger test killed the whole suite with exit 2 and reported nothing. Gate a process-ending test on something the caller must set (an env var), and tag it as well.
- `\n` written to stderr comes back as `\r\n` when a child's stderr is redirected to a file on Windows (text-mode stream). A marker contract spelled with `\n` in a doc must be matched as "line ending", not as those two bytes.
- Patching a source file through this shell's heredoc eats one backslash: `\n` in the Python source arrived as a real newline and broke three string literals. Build escapes with `chr(92)`, or edit the file directly.
- `CreateProcessA`'s `lpCurrentDirectory` must be an absolute path; a relative one is unreliable and, worse, a `WaitForMultipleObjects` array holding a handle from a failed spawn doesn't error out - it returns `WAIT_FAILED` and a naive retry-the-same-wait loop spins forever, which looks exactly like a hung test suite from the outside (found building the W1 runner lane's `--isolate` pool). Always resolve the private-cwd path to absolute before the spawn call, and treat `WAIT_FAILED` as "every active handle is presumed dead," not as "wait again."
- `taskkill /IM <name>.exe /T` kills every process with that image name on the machine, not just the one you started - on a two-PC-worktree setup with several lane sessions running concurrently, this silently kills a sibling worktree's in-progress `tl_tests.exe` run. Kill by exact PID (from your own spawn or `wmic process where "CommandLine like '%your-worktree-path%'"`), never by bare image name, when other sessions might be running the same binary.
- An exhaustive property test tagged `slow` (2^30 iterations) left running under `--isolate` with no `--tag !slow` looks identical to a deadlock from the outside (one lone child process, no output, past any reasonable timeout) - it is just the straggler once every fast test has finished. Check what the lone survivor's `--run-one` index actually is (`tl_tests --list`) before concluding the pool hung; the PR lane's own invocation (`docs/TESTING.md` §9.3) already excludes `slow`.
- **A counter nobody reads is not a gate.** `TestCtx::checks` was incremented by every assertion macro in the runner and read by nothing, so a test whose checks all sat inside an untaken `#if` - the tier-conditional shape this file mandates - reported PASS having executed nothing. Six of them were live. Whenever you add a counter to prove work happened, add the line that FAILS when it is zero, in the same commit.
- **A failed spawn is not evidence.** A `CreateProcess`/`fork` failure that sets an "it terminated abnormally" flag makes every fatal-expected test pass: a broken exe path turns the whole fatal suite green while running none of it. Check "did it start" before interpreting "how did it end", always, and never let a not-run path share a code with an expected-outcome path.
- **A template with no call site has never been compiled.** `NEAR_FX`/`SPAN_EQ`/`MEM_EQ` shipped as "completed" with zero instantiations anywhere in the tree, so no compiler had type-checked them; the first one written found a signed-overflow UB in the ulp difference. A generic helper is not code until a test instantiates it.
- **A selection that matches nothing must be an error, not a clean run.** Third occurrence of the empty-list silent pass (after the cross-target gate and the record comparison): `tl_tests --tag <typo>` printed "0 run, 0 failed" and exited 0, and the PR lane's invocation is `--isolate --tag !slow`. Any filter, glob or tag that can select zero items needs a zero check beside it.
- **`atoll` answers 0 for `abc`, `` and `12x`.** `tl_driver --seed abc` was a silent seed 0 and `--ticks abc` a silent zero-tick run, in a binary whose contract is byte-identical output for the same seed. A CLI that takes numbers needs a strict parser that rejects, not a C library call that guesses.
- `docs/ROADMAP.md`'s dependency graph lists a lane's headline deps ("platform: skeleton"), not every type its implementation spec actually needs mid-build: `PLATFORM.md` §9.5 allocates impl state from mem's `VMemArena` in its very first init step, which the graph doesn't surface as a platform dependency at all. Read the target doc's implementation spec for real blocking types before trusting the wave graph's dependency column.
- `tools/audit/includes.py`'s contract-comment gate matches a struct's `RetType (*name)(args)` function-pointer field only if the FIRST paren pair it walks ends in `{`/`;`/etc: for a bare-identifier return type (`void`, `u32`, `ErrCode`...) that first pair is the pointer-declarator's own `(*name)`, whose close is immediately followed by the real `(args)` - starting with `(`, which the accepted-suffix list excludes - so it always reads as "not a function" and needs no comment. A macro that expands a helper's `{ return ...; }` onto its own physical line does NOT get this exemption - each such line is its own declaration site and needs a real comment above it, same as any hand-written function.
- `arena_push` aligns a push's START (`align_up(used, align)`), never its SIZE - `end = start + bytes` with no rounding (`MEMORY.md` §8.2, measured against the real `vmem_arena.cpp`, not the doc's pseudocode). A caller whose own contract promises an aligned GROWTH (`PLATFORM.md` §9.6 `read_all_contract`: "`used` grows by exactly `align16(len+1)`") has to round the SIZE it asks for itself; passing `align` alone silently leaves `used` unaligned whenever the payload length isn't already a multiple of it.
- A "no stray tmp file" promise on an atomic-write crash-safety test is a promise about the FINAL, uninstrumented call - not about every killed one. `write_atomic`'s temp file legitimately survives a kill at "after write" or "after fsync, before rename" (the process died before the rename that would remove it); asserting tmp-cleanliness inside the per-kill-point loop fails a design that is working exactly as specified. Check only what the doc actually promises at each point: the TARGET file's integrity during the loop, tmp-cleanliness only after the real call.
- A trigger test gated on an env var (`getenv(...) == nullptr) return;`) reports FAIL, not a silent no-op, when run bare without `--filter <name>` + the var set - the runner's zero-checks-is-a-failure rule (`TESTING.md` §1) applies to it like any other test. This is by design (matches `tl_assert_forced_fatal_trigger`'s own precedent): the trigger is misuse outside its one sanctioned call path, and the PR lane's `--isolate --tag !slow` never reaches it. Confirmed, not "fixed", when a slow-tagged trigger test fails under a manual `--tag slow` run with no env var set.
- **`windows.h`'s raw `min`/`max` macros mangle any declaration of a same-named function that comes after them.** `fx.h` declares free functions `min`/`max`; `tests/foundation/vmem_test_api.h` (`#include <windows.h>` with no `NOMINMAX`) had never been included from the same TU as an fx-family header until the W1 containers lane's `sort.test.cpp` (via `rng.h`) did - "too many arguments to function-like macro invocation" is what a mangled `constexpr fx<Rep,F> min(...)` looks like from clang, not an obvious min/max collision message. `NOMINMAX` before `<windows.h>`, always - now a rule for the whole tree rather than advice, enforced by `tools/audit/includes.py` gate 7 (`PLATFORM.md` §9.1), which is the one gate that walks `tests/` as well as `src/`.
- **`vmem_arena_init` rounding the reserve to the page size, not `COMMIT_GRANULE`, is not just a mem-lane test gap.** A `SlotMap` domain whose per-column bytes (`sizeof(element) * (IDX_MASK+1)`) land under 64 KB - true of most test geometries and some real small resource-handle pools - TL_FATALs "arena over reserve" on its very first `arena_push`, because the first commit always rounds its *want* up to a full `COMMIT_GRANULE` regardless of how small the reserve was. The fix landed on main the same day (`vmem_arena_init` rounds every reserve up to `COMMIT_GRANULE`, `docs/MEMORY.md` §8.2), and the caller-side floors written against the old behaviour are now dead code - delete them when you merge, do not leave them "harmless".
- **"Two instances, same op sequence" is the weakest determinism test that still looks like one.** Five of them shipped in the W1 containers lane and not one could see that `Array` and `Map` were leaving removed elements' bytes inside the hashed extent - both instances got the same garbage. The property worth testing is DIVERGENT histories that converge: build the same logical state two different ways and compare bytes. Where that is false by design (a ring's state is its two free-running counters), test the negation and say so, so nobody "fixes" it later.
- **A vmem-backed `Array`'s hashed extent is its whole committed capacity, not `[0, count)`** - the arena's `used` tracks `cap`. So `pop`, `swap_remove` and `clear` are determinism operations, not bookkeeping: whatever they leave above `count` is hashed. `ARENA_ZERO_ON_PUSH` does NOT clean it up on refill (it only re-zeroes bytes an `arena_push` actually walks over, and an in-place refill pushes nothing) - a sentence in `CONTAINERS.md` §8.1 claimed it did, and that claim is why the bug shipped.
- **Never let a container assume `arena_push` hands back zeros.** Fresh pages are zero; anything below the arena's `high_water` is zero only under `ARENA_ZERO_ON_PUSH`. `Map`'s `state` array assumed it, and a `Map` built from a reused arena reads every slot as FULL - so `map_probe`'s "walk to the first empty slot" never terminates. A hang, not a wrong answer.
- **A "reference implementation" oracle has to consume the output under test.** The 1M radix test insertion-sorted a *second* random array and asserted that array was sorted; it never read the sort's output, so every radix bug passed. Sort a copy of the SAME pairs and compare element-for-element - and check the value column is a permutation of the input indices, which is the cheapest way to catch "lost or duplicated an element".
- **A single-shot parallel test cannot see a job-to-job lifecycle bug.** Reintroducing the W1 jobs lane's R-4 defect (the barrier counting completed CHUNKS, so the worker that zeroes the count is still inside its claim loop and does one more `fetch_add` on a counter the next job has already reset) was caught by the contention soak and by **nothing else** - the worker-invariance sweep, the levels test, the scratch test and both shuffle tests all passed, at every worker count, because each runs one job per pool. The bug lives in the window between one job's last retire and the next job's publish. Any pool, queue or arena with a reuse cycle needs a test that runs the cycle thousands of times back to back, and that test's checker has to be in the fast lane - slow-tag it and the defect ships.
- **A balanced scratch scope leaves `used` at 0, so `used > 0` is not evidence that work happened.** A jobs test asserted `arena_mark() > 0` after 512 chunk fns had each pushed 4 KB and popped it; the arenas had done real work and the assertion was simply wrong. `high_water` is the field that remembers, and it is what a "these arenas were actually exercised" check must read.
- **A checker that spawns its own timed child must give it a deadline UNDER the lane's per-child budget** - the lane kills the checker at its budget and a deadlocked grandchild with a longer deadline is ORPHANED past that kill (measured: two orphaned soak triggers at 180 s under a 120 s lane budget squatted on tl_tests.exe and failed the next build with "permission denied"). The grandchild's timeout is deadlock detection, not headroom; size it from the child's real runtime, not from generosity.
- **An epoch guard (`if (e == seen) skip`) turns a counter wrap into a permanent stall wherever one side can advance without the other observing** - the jobs inline path advanced a u32 epoch without waking workers, so exactly 2^32 inline jobs between two pooled ones re-equalled a worker's `seen` and parked it on a real token. A compare-for-equality freshness token must be too wide to wrap (u64), or every advance must be observed by every comparer.
- **A double shadow is the first thing to run on a fixed-point failure, not the last.** Three of the W2 gate0 lane's "row failures" were solver design (an owner-only PBF pass launching a landing block, corner-order friction drifting a stack, a wall edge on an interior face) and the double world did every one of them identically; the one real row effect (per-constraint `lambda_t` narrowing creeping a resting box 12 quanta/tick) was the one where the double sat still. Attribution before ladder-climbing, every time.
- **Substepping amplifies an unconverged position correction by 1/h.** A one-pass PBF over-corrects a landing by ~3x; at 60 Hz that is a slow ripple, at 480 Hz the same 6 mm becomes a 2.9 m/s launch because v = dx/h. A constraint that is not converged per substep needs compliance scaling with h^2 or it needs iterations - more substeps make it worse, not better.
- **An analytic box SDF is ambiguous at every corner, and an aligned stack is nothing but corners.** `max(|lx| - hw, |ly| - hh)` at a corner-on-corner returns the x-axis normal on a tie; the whole stack got horizontal pushes and toppled. Break the tie with the querying body's centre, and never let a static wall's EDGE lie on another wall's interior face (a particle in the corner then reads the edge and is pushed through the floor).
- **A neighbour list that carries a support margin needs the capacity of the margin, not of the kernel.** Lists at radius h + travel hold ~50 at rest; capped at ALLOY's 64 they overflowed under 30% compression, the dropped neighbours under-estimated rho, and the liquid collapsed into itself - a cap on a list is a silent change to the physics.
- **"Any saturation is a FAIL" needs every narrowing to COUNT, not assert.** The first G-02b run died on a `TL_ASSERT` in a helper (a plank spun a quarter turn per substep); a bench that aborts on the very event it is meant to grade reports nothing. Clamp, count, print the count on the verdict line.
- **A bench that stops early must stop its statistics too.** `tl_gate0` kept `cost[ticks]` sized to the requested tick count, so a G-05 run that escaped at tick 139 of 500 took its p50/p95/p99 over a zero tail (every percentile 0), suppressed its own verdict line, and the README's cost numbers had to be hand-derived from a CSV column. Percentiles over the ticks that RAN, and the cost detail printed on the failure path too - a FAIL's cost is evidence, its verdict is not. Same class: a double shadow with no escape stop reports the distance a runaway particle travelled as "max |fx - double|"; read the ticks before the ejection.
- **Measure the kernel's ops before blaming the arithmetic.** RR-13's "fixed-point premium ~5-10x" was an estimate; a 40-line micro-benchmark of the pair body as spelled gave 176 ns fixed vs 5.5 ns double (32x), of which 125 ns was two bit-serial `isqrt64` calls and 51 ns three i64 divides - the kernel called `length()` and then `normalize()` (a second root) and divided by h separately. The palette rows contributed 4 ns. A cost verdict on a number system needs the op count and the per-op cost on the table, or it grades the implementation.
- A threshold and its measurement protocol must name the same core count. G-05's "4 ms at 20k" was `ALLOY.md` §11.2's ~8-core budget graded against a single-thread run — unreachable by ANY scalar arithmetic including double, which silently voided the pre-committed float-fallback clause it was supposed to arm (`GATE0-BENCH.md` §7 R-3).
- Derive a row's range from its structural cap, not its nominal domain. `omega_t` carried ±2,048 turn/s while `pθ = θ − ω·h` caps |ω| at `inv_h/2` = 240 by construction — ~90 % of the range was unreachable headroom that cost 4× resolution until Gate 0 measured it (`FX-PALETTE.md` §9 R-8).
- A scenario criterion that says "nothing fails" grades whatever is weakest, not what the scenario exists to test. G-02b existed to test the boulder's 4096:1 contact and its letter graded the feather's ejection (`GATE0-BENCH.md` §7 R-5). Name the body the criterion is about.
- A CSV named only by (scenario, substeps, ladder) lets a later probe run silently overwrite an earlier verdict's evidence: the `--perturb` probes re-wrote `G01_s8_l1.csv` over the 10k-tick verdict's trace — the exact class the W2 review's D3(c) already caught once. Probe runs get their own out dir, and a replaced CSV gets its verdict line re-compared, not trusted.
- A rounding change below the storage quantum is invisible at rung 1 and state-visible at rung 3: the normalize-once reciprocal disagrees with the two-division normalize on ~1.6 % of pairs (sampled), yet the l1 particle traces reproduced rev 1 bit-for-bit over 7,000 ticks — the grad/correction/writeback RNE layers absorbed every sub-quantum difference — while `--ladder 3` diverged at tick 20 because the residual carry stores exactly the bits the round discards. Test a kernel-rounding change against the ladder rung that can see it.
- A per-tick state hash compares ENCODINGS, not physics: retuning `omega_t`'s FRAC moved every body-scenario hash from tick 0 even where the motion is unchanged. When a row's format moves, expect full-trace deltas on any scenario whose arenas store that row, and judge those scenarios, never diff them.
- A CMake build dir bakes in the absolute path of the cmake.exe that configured it (VerifyGlobs re-runs it on every build); a removed portable CMake install poisons `cmake --build` even after the new CMake reconfigures — if configure itself keeps failing inside the old dir, delete the build dir rather than fighting the cache.
- A mechanism that exists twice has two failure paths: the isolate pool failed a broken waitpid loudly while the serial half decoded the same failure's zero-initialized status as PASS, and the driver's strict flag parser never reached the runner's identical atoll flags. When fixing a class, grep for its twin before calling it fixed (W1 wave-boundary sweep D1/D2).
- **A `World`-sized fixture on the stack is a Windows-only crash**: `comps[1024]` makes a World ~256 KB, a Windows child process gets a 1 MB stack (Linux: 8 MB), and one test held four fixtures - every Windows CI leg failed in suites that were green locally. Reproduce the constraint, don't guess at it: `ulimit -s 1024` found it in one run. Big fixtures live in statics (tests are exempt from the src/ static ban).
- **A test that violates the contract it tests can pass exactly where you run it.** The bytes hostile-length row passed n = 2^64-1 with a 1-byte out buffer against an API whose error path zero-fills all n bytes BY CONTRACT; dev -O1 happened to fold the doomed memset away (green locally) while debug/Windows/ASan all crashed. When a test probes a bound, first ask what the contract obligates the CALLER to provide at that bound.
- **The docs-commit gate is per-commit and per-module-directory.** A `src/foundation/` commit that documents itself in ECS.md (another module's doc) still needs `[docs:none]` - and a missing marker on an already-pushed commit means history surgery, because the per-commit walk re-runs on main forever after the merge. Check `commit_docs.py --base origin/main` locally before every push, not after.
- **When two states share every byte, the discriminator must be an out-of-band record, not another byte test.** A pending reused spawn reservation and a stale handle to a quarantined slot are both dead + generation-matching; `gen != GEN_MAX` looks like a fix and silently loses destroys for the 1/1023 last-generation case (a free-list slot legitimately sits at GEN_MAX). The window's popped-idx set - a transient record of what actually happened - is the exact separator.
- **Realize-order assumptions must survive the external chunk**: it RECORDS first (app/editor code runs between barriers) and APPLIES last (chunk id = system count), so "reservation order == apply order" is false for exactly one legal caller. Any barrier-applied invariant needs a trace with the external chunk in the interleaving before it ships.
- **"Commit and push every turn" reads two ways, and an autonomous lane picked the wrong one:** as a floor (never leave work unpushed) it is correct; as a ceiling (end the turn at each commit) it turns an unattended lane into a babysat one - the net-p1 lane stopped four times to "report status" nobody asked for. A rule written for sync discipline must say which direction it binds, and an autonomous brief must name its ONLY stop conditions explicitly (`WORKFLOW.md` §1 R-6); the commit trail IS the status report.
- **Second occurrence of the "trust the wave graph's dependency column" class (see the `PLATFORM.md` §9.5 / `VMemArena` line above), and this time it blocked a whole lane.** `ROADMAP.md` §2's net-p1 row names `TL_WIRE_STRUCT` and stops; `NETCODE.md` §20's implementation spec also needs `InputFrame`/`ActionState`/`MAX_ACTIONS` (`core/input.h`, a W3 lane's file) for the encoder, needs the `Replay` producer to close Phase 1's own done criterion, and calls `ByteWriter`/`ByteReader` - a pair named only in `ECS.md` §10.2 and defined in no doc at all. Before launching any lane, resolve every type its spec's structs and algorithms mention to an owning doc AND a file that exists on `main`; the ones no doc owns are the expensive find, because nothing fails until two lanes have each invented one.
- **A per-block header is free until you divide by the block size.** `NETCODE.md` §20.2.9's archive segment is a 112-byte header closing every `CHECKPOINT_HOT_TICKS` (300) ticks, plus an 8-byte stream header per (slot, channel). Over 30 minutes at 3 peers that is 360 segments: 39 KB of segment headers and 54 KB of stream headers around 31 KB of actual transition records - **75% framing**, against a < 80 KB gate. Taken literally ("for ch in 0..35") it is worse: 810 KB of stream headers alone at 8 peers, against a §13.4 target of 165 KB TOTAL, which is how the contradiction was spotted - the doc's own size table disproves the doc's own layout line. Two habits from it: when a format states both a per-block framing cost and a total-size target, divide one by the other before writing the encoder; and when a size gate fails, measure the split between framing and payload before touching the fixture, because a fixture that is already LIGHTER than the spec's own activity model (4,206 transitions/peer against a stated 5,000-8,000) cannot be the cause.
- **A fuzz round-trip only proves canonicality if the format has exactly one encoding per value, and "decode succeeded" is not that property.** T1f's `NETCODE.md` §20.6 wording - a mutated stream "is refused or decodes to something re-encodable identically" - failed on a mutation that CLEARED a `changed` bit: the stream still decoded, consumed fewer bytes than it was given, and re-encoded three bytes shorter. The fix was reading §20.2.2's rule as the biconditional it is written as ("bit a set <=> actions[a] != prev.actions[a]"), so a set bit decoding to the state the action already had is refused. Non-minimal varints and a value byte carrying the implied value are the same class. This matters beyond tidiness because §20.2.8 hashes archive bytes into `ChainEntry.log_segment_hash`: two encodings of one frame set fork the chain with no divergence behind it. Any format whose bytes are hashed needs its decoder to refuse every non-canonical spelling, and the test that finds them is mutation fuzz with a re-encode comparison, not a round-trip.
- **A test that reuses one stack buffer across cases must clear the bytes it does not write.** T0 fills every non-pad field of each wire struct from a table and leaves pads alone - correct, since a nonzero pad is what the refusal row tests. Reusing one `u8 src[256]` across 23 structs meant each struct's pads held the PREVIOUS struct's bytes, so the writer emitted nonzero pads and the reader correctly refused them: 14 failures that read exactly like a codec bug in the reader. Zero the row before filling it; more generally, a "fill the interesting fields" helper over a shared buffer is only correct if it also owns the uninteresting ones.
- **A round-trip test cannot see a format with two spellings; only a mutation fuzz with a RE-ENCODE comparison can.** The net-p1 archive shipped six T2 rows in which every byte was produced by the encoder under test and handed straight back to the decoder. Its adversarial review found four canonicality holes in an afternoon with a 40-line harness that mutated a payload byte, repaired the two crc32s, decoded, and re-encoded: an escape record could move the `down` bit that the action channel already carried; a slot could appear in `slot_mask` with no streams at all; channel 35 aliased onto the escape channel because `ARCHIVE_CH_COUNT` copied a doc typo; and a zero-tick segment encoded but could not decode. 8,677 of 128,319 mutated-but-decodable segments re-encoded to different bytes. The lane had ALREADY written the lesson ("the test that finds them is mutation fuzz with a re-encode comparison, not a round-trip") for the column codec and then did not apply it to the archive - the format whose bytes are actually hashed into the chain. Write the fuzz for every format you hash, and repair the checksums inside it or it only ever tests the checksum.
- **`TL_ASSERT` is not a precondition check; it is a dev-tier comment.** Three separate defects in one lane: locals used only inside an assert became unused-variable errors under `-Werror` on netcode/ship (11 of 23 CI legs red while dev and debug were green); the column encoder's "flags fit three bits" guard vanished on exactly the two tiers that ship, where `flags & 7` then truncates silently and every receiver applies a different frame than the sender; and the archive encoder's slot-ordering contract vanished the same way, where violating it produces a segment that is written, hashed into the chain, and then permanently unreadable. If violating a condition corrupts data or produces UB rather than merely indicating a bug, it is `TL_CHECK` - `bytes.h` already draws that line ("a producer that blows its own buffer is a bug ... TL_CHECK, all tiers") and the rest of the tree should match it.
- **An expansion loop that re-fills the tail is quadratic, and a per-block cap hides it until someone raises the cap.** The archive's transition decoder wrote `for (i = tick; i < tick_count; ++i)` per record instead of filling `[tick, next_tick)`. At `CHECKPOINT_HOT_TICKS` = 300 it is 0.14 ms and invisible; at 18,000 ticks it was 199 ms and at 60,000 ticks 4,557 ms, against 15 ms to encode the same segment - a 129x asymmetry an untrusted peer chooses the size of, since §20.2.5's `BK_LOG_SEGMENT` arrives over the wire. Fixing it to close the previous run at the next record's tick: 35 ms at 60,000 ticks. When a decoder's cost depends on a length the wire supplies, measure it at ten and a hundred times the current cap, not at the cap.
- **A revert experiment that does not check the BUILD reports false confidence.** Verifying that a regression test actually catches its defect means reverting the fix and watching the suite go red - but a revert that fails to compile leaves the previous binary in place, and the runner then reports the OLD build passing. Four "the test does not catch this" results in the net-p1 round-3 sweep were that artefact (`-Wunused-but-set-variable` on a now-dead local), and one genuine result was hidden among them. Any revert harness must fail loudly when the build fails, before it interprets a test result - the same rule as "an empty selection must be an error, not a clean run", one layer down.
- **A negative test can be refused for the wrong reason, and then it pins nothing.** Three of net-p1's new archive rows passed while the rule they named was reverted, because the forged segment tripped a DIFFERENT check first: an empty stream spliced out of (slot, channel) order was refused by the ascending-key rule, log records spread across ticks were refused by the effective_tick range rule when the tick count shrank, and a swapped escape pair tested ordering rather than the no-op refusal. When writing a test that asserts a REFUSAL, construct the forgery so that exactly one rule can object - and prove it by reverting that rule and watching the row go red. Otherwise the row is only evidence that something, somewhere, said no.
- **Named padding is written, so it must be initialized — and a zeroed stack hides the bug.** Shrinking the archive segment header left a 4-byte `_pad1` after `header_crc32` (the struct carries a `u64`, so it aligns to 8). The encoder never set it, so it put stack bytes on the wire, and the decoder correctly refused them as a nonzero pad — but only sometimes, because the first encode of a run usually lands on zeroed stack and the second does not. What caught it was the archive's mutation fuzz comparing a re-encode byte for byte: `diff@52, buf=00 again=FD`. A round-trip test would not have, since both halves of a round trip see the same garbage. Any `_padN` a wire struct declares is a field the writer owns; treat "explicitly padded" as "explicitly zeroed on every write", and let a re-encode comparison be what proves it.
- **A wire-format change retires the test corpus that guarded the old one, silently.** The net-p1 archive's option-A change (fixed 8-byte stream headers to two uvarints) left a hand-spliced forgery in the regression suite still writing the OLD header. Those bytes now parsed as several `record_count=0, key=0` headers, so the segment was still refused - by a different rule - and the row kept passing while the rule it named went untested: deleting that rule left all 60 rows green. Two habits: after changing a byte layout, re-run the revert experiment for every row that hand-writes bytes, not just the suite; and treat a passing negative test as unproven until the rule it names has been reverted under it.
- **A fuzz corpus can be overwhelmingly one shape and still look broad.** The archive mutation fuzz generated a million segments in which **97.2% of all streams were pointer streams and 22 in total were escape streams** - because the fixture toggled a button once per 64 ticks and the segments were 5 ticks long (0.23 toggles per segment), and because it constructed derived-consistent edge flags, which is exactly the case the escape channel does not carry. Two real second-spellings survived 10^6 cases for that reason. When a format has channel families, count what the corpus actually produced per family before trusting the case count; a big number is not coverage.
- **A steward window's context is spent by mechanical reads, not by thinking.** One orchestrator window burned most of its budget on three ~72 KB CI job listings, run listings that return full commit bodies for 25+ runs, and raw log tails — all read by the most expensive model. The cures are mechanical and are now `WORKFLOW.md` §6 R-10: SHA-targeted queries with `per_page` 1–3; parse every oversized tool result from its saved file with python instead of re-fetching; hand log harvesting to a cheap-model subagent that returns five lines; retire the window at a phase boundary — the committed-file handoff makes a fresh one cheap by design.
- **A red CI round is billed twice.** The lane pays a fix cycle and the steward pays an investigation, on separate sessions' budgets. Local validation before every push (`WORKFLOW.md` §6 R-11) is token policy, not just hygiene.
- **A vendored C++ library is only "pooled" if every part of it has a hook, and Luau's does not.** `MEMORY.md` §2's premise is that vendor libs route through `mem_pool` via their hook APIs; measured at the 0.696 pin, the Luau **VM** does exactly that (`luau_load` + `lua_pcall`: **zero** global `operator new`), and the Luau **Compiler** — which has no hook API at all — makes **32** per `luau_compile`. The dev/netcode alloc-shim tripwire turns that into a `TL_FATAL`, so an in-process compile kills the suite in the two tiers the done criterion names, while `debug` and `ship` (no tripwire) stay green and hide it. Check the hook coverage of every COMPONENT of a vendored library, not of the library.
- **A context-free C callback cannot reach engine state under a writable-static ban.** Luau's `useratom` is `int16_t(*)(const char*, size_t)` — no `lua_State*`, no userdata — so the specified "return the interner's `StrId`" needs a namespace-scope pointer that `CPP-SUBSET.md` §1 bans. Third instance of the class (the CRT-malloc counter, `vendor_glue`'s static pool pointer, this), which is the argument for one general mechanism rather than three exceptions. Read the CALLBACK SIGNATURE before speccing what the callback consults.
- **A gate token written before the thing it gates is vendored fires on the wrong file and never on the right one.** `BACKEND_HEADERS`'s bare `"luau"` predated the vendoring: upstream spells its headers `<lua.h>`/`<lualib.h>`/`<luacode.h>` and `Luau/*.h`, so the token matched no real include — while it DID match our own `#include "vendor_glue/luau_alloc.h"`. Re-derive a speculative gate entry against the real tree the day it lands.
- **`luaL_checklstring` makes stock `%s` type-error on a table; Luau's `%*` extension prints the address.** The sandbox's `string.format` wrapper has to intercept `%*`, which no doc named, more than `%s`, which every doc did. `%p` needs nothing — Luau rejects it as an invalid option. Read the vendored implementation before deciding which conversion leaks.
- **The runtime's only sort is an integer radix with no comparator.** `CONTAINERS.md` §4's `sort_u32_kv`/`sort_u64_kv` cannot express "numbers before strings, then bytewise", and §6 puts the only comparison sort in `tools/`. A spec that says "sorts with the foundation sort" over mixed keys is naming a function that cannot do the job; the caller carries its own stable merge.
- **An oracle that asserts its own preconditions cannot be asked whether it is in range.** `fx::div<q_t>(a, b)` traps when the quotient leaves `q_t`; computing `want = div(...)` and *then* range-checking `want` traps before the check runs. Compute the raw quotient with `rne_div` first and sweep only the in-range pairs — the same "generate inside the contract" rule, applied to the ORACLE rather than to the generator.
- **A negative fixture built on a base layer that already violates something passes on the wrong violation.** Four new `symbols.py` rows used the `lower` fixture, which carries a deliberate upward reference, so every one of them saw `rc == 1` for a reason unrelated to the plant. Build a negative row on a base that is otherwise clean, and assert the MESSAGE names the planted symbol.
- **A lane brief's environment claim is a hypothesis, not a fact.** This lane's brief said "`netcode`/`ship` refuse configure" in the container, so the first two pushes were validated on `dev`+`debug` only — and the netcode/ship `-Werror` unused-parameter break (the `#if TL_DEV` body class already in this file) took eight CI legs red. `-DTL_STRICT_TOOLCHAIN=OFF` configures all four presets here. Try the thing the brief says is impossible before scoping local validation around it; a red CI round is billed twice (`WORKFLOW.md` §6 R-11).
- **`operator new` is replaceable per PROGRAM and nowhere narrower — so a vendored library that allocates with it forces a program-wide decision.** The cure that kept every existing rule: split the tripwire operators into their own archive member so ordinary archive semantics let a replacement win with no duplicate symbol (they had shared a member with the anchor the guard force-pulls), then open a bounded WINDOW around the one call that needs it and charge the bytes to the pool that call is for. Outside the window the replacement fatals exactly like the tripwire, so the ban is unchanged where it was doing work.
- **A per-test copy of a process-stable resource trips the guard that protects it.** `StrId` is process-stable by CANON, so `script_install_useratom` fatals on a second, different `Interner` — and a fixture that built one per test hit it on test two. The fixture was wrong, not the guard: a shared process interner in a function-local static is what the real program has.
- **Both halves of a two-key exemption need their own planted violation.** `tools/audit/static_allow.txt` is keyed by (lib, directory, stem); the fixtures plant the exempt directory at a different stem AND the exempt stem in a different directory, for each row. RR-7's original defect was exactly a stem-only match, and one fixture per row would have re-introduced it in the new file.
